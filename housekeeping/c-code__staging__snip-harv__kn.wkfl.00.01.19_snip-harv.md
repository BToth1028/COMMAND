# Workflow: Snippet Harvesting

**Purpose:** Extract reusable code snippets from existing source files using semi-automated workflow
**Type:** Orchestrator - scans code, filters noise, user triages, stores approved snippets
**Note:** Atomic operations delegated to harvester script (`to.genr.03.07.21_snip-harv.py`) and Snippet Storage workflow

---

## When To Use

| Scenario | How You Get Here |
|----------|------------------|
| New project imported | After quarantine, harvest useful patterns |
| Existing tools to document | Extract snippets from working code |
| Consolidating patterns | Find duplicates, keep best version |
| Building snippet library | Systematic extraction from codebase |

---

## Scope

| Applies To | Excludes |
|------------|----------|
| `.py`, `.js`, `.ts`, `.css`, `.sql`, `.ps1`, `.sh` files | Binary files |
| Functions, classes, patterns | Test files (`test_*.py`) |
| Standalone reusable code | Project-specific config |
| Code blocks in any source file | One-line assignments |

---

## Preconditions

- [ ] Source folder/files identified
- [ ] Harvester script available: `to\genr\03.07\21\py\to.genr.03.07.21_snip-harv.py`
- [ ] Snippet library exists: `li\code\snippets\`
- [ ] v3.1 specification understood

## Phase 1: Scan

### Run Harvester Script

```powershell
python "C:\dev\to\genr\03.07\21\py\to.genr.03.07.21_snip-harv.py" --source "path/to/scan" --output candidates.json
```

### Noise Filter Criteria (Auto-Skip)

| Criterion | Threshold | Rationale |
|-----------|-----------|-----------|
| Code length | < 5 lines | Too small to be useful |
| Code length | > 300 lines | Too large for a snippet |
| Function name | `test_*`, `_private` | Test/internal functions |
| No function/class | Just loose statements | Not reusable |
| Import-only | Only import statements | Not code |
| Duplicate hash | Already in library | Dedup |
| Config/constants | Just `FOO = "bar"` | Not patterns |

### Extraction Methods

| Language | Method |
|----------|--------|
| Python | AST parsing (accurate) |
| JavaScript/TypeScript | Regex (function/class detection) |
| CSS | Regex (selector blocks) |
| SQL | Regex (CREATE/SELECT statements) |
| PowerShell/Shell | Regex (function blocks) |

## Phase 2: Triage

### Candidate Presentation Format

```
=== SNIPPET CANDIDATES ===
Scanned: 12 files | Found: 47 functions | Filtered: 32 noise | Candidates: 15

#   Language   Type      Lines  Title                      File
--- ---------- --------- ------ -------------------------- ---------------------------
1   python     function  23     parse_config               tp/App/form_app.py:45
2   python     class     67     SqliteAdapter              tp/App/form_app.py:120
3   javascript function  18     showModal                  pr/Meta-Recr/sr/static/main.js:89
4   javascript function  12     apiCall                    pr/Meta-Recr/sr/static/main.js:205
5   css        pattern   34     .modal-overlay             pr/Meta-Recr/sr/static/style.css:156
...

Enter numbers to extract (e.g., 1,3,5 or 1-5 or all): _
```

### Selection Syntax

| Input | Meaning |
|-------|---------|
| `1,3,5` | Extract items 1, 3, and 5 |
| `1-5` | Extract items 1 through 5 |
| `all` | Extract all candidates |
| `none` or empty | Cancel, no extraction |

## Phase 3: Enrich

### v3.1 Field Auto-Fill

| Field | Auto-Fill Method |
|-------|------------------|
| `$schema` | `"snippet-v3.1"` |
| `title` | Extract from function/class name |
| `id` | `snip-{lang}-{slug}` from title |
| `type` | Detect: function, class, pattern, utility, query |
| `language` | File extension mapping |
| `tags` | Pattern keyword detection |
| `contexts` | Infer from language (frontend/backend) |
| `complexity` | Line count + nesting depth |
| `requires` | `[]` (user fills if needed) |
| `provides` | Function/class names found |
| `pip_packages` | Extract from Python imports |
| `npm_packages` | Extract from JS imports |
| `system_deps` | `[]` |
| `css_requires` | `[]` (user fills for JS) |
| `html_elements` | `[]` (user fills for JS) |
| `html_template` | `null` |
| `config_keys` | `[]` (user fills) |
| `env_vars` | `[]` |
| `init_functions` | `[]` |
| `init_order` | `null` |
| `schema` | `"generic"` |
| `integration_style` | `"standalone"` |
| `api_endpoints` | `[]` |
| `side_effects` | Detect from code patterns |
| `tested_with` | `{}` |
| `has_tests` | `false` |
| `has_example` | `true` |
| `status` | `"active"` |
| `source_file` | Original file path |
| `source_lines` | Line range |
| `origin` | `"extracted"` |
| `created` / `updated` | Today (YYMMDD) |

### User Must Provide

- **description**: One-line explanation of what this does
- **config_keys**: If code reads from config file
- **html_elements**: For JS: DOM IDs it expects
- **init_order**: If order matters (lower = earlier)

---

## Phase 4: Store

### File Creation

For each approved snippet:

1. Generate filename: `snip-{lang}-{slug}.md`
2. Write to: `li/code/snippets/snip-{lang}-{slug}.md`
3. Add to: `li/code/snippets/by-language/{lang}.md`
4. Add to: `li/code/snippets/by-pattern/{pattern}.md` (for each tag)
5. Add to: `li/code/snippets/index.md`

### Verification

| Check | How |
|-------|-----|
| File exists | `Test-Path li/code/snippets/snip-{lang}-{slug}.md` |
| Frontmatter valid | All required v3.1 fields present |
| Language index updated | Entry appears in by-language/{lang}.md |
| Pattern indexes updated | Entry appears in by-pattern/{tag}.md for each tag |
| Master index updated | Entry appears in index.md |
